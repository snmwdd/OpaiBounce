# Opai for LiquidBounce

把工作区 `Opai-Samsara-Shell.zip` 中的 Opai 界面移植为 LiquidBounce Nextgen 网页主题。首次公开免费版为 **0.1.0**（开发版 1.12.2 的后续），主题 ID 为 `opai`，默认使用 Light Pink 配色。源码与集成基线是本工作区提供的两个压缩包。

## 免费 0.1.0 发布候选

- HUD 使用同一坐标平面和原生缩放快照；迟到的请求不能覆盖更新的缩放事件。编辑和覆盖层采用同样的锚点及比例，窗口缩放时取消正在进行的拖动；保存失败恢复原位置。
- 账号管理加入 My / Nfa / Offline 初始文件夹、账号数量、嵌套、新建、重命名和移动。双击或选中后 Open Folder 进入；Root folder / Back 返回上级。颜色继续使用 Light Pink。
- 分组用登录类型和 UUID 保存，原生列表编号变化后仍能找到正确账号。删除文件夹只移动内容到上级；删除账号才调用原生删除接口。
- 文件夹写入失败保留旧状态并显示错误；损坏的分组元数据不会阻止访问 Root 中的账号，首次修复保存前保留 recovery 副本。主题包不含个人账号或登录信息。
- 账号登录成功接入灵动岛通知动画，显示实际账号名后自动收起；通知期间隐藏账号页标题，避免重叠。
- Bridge 仍为 1.4.2，Java 音乐服务仍为 1.2.0。需要完整的主题和一份匹配脚本，不需要替换客户端 JAR。

本次为发布候选：浏览器隔离回归可验证功能与坐标，不代表 Windows / macOS 原生 CEF 性能验收。Windows 10 的约 60 FPS 相比旧版约 500 FPS 的反馈仍缺少原机对照数据，不能标记为已彻底解决。发布说明应保留此限制。

账号文件夹保存在主题持久化键 `opai.accounts.folders.v1`，账号本体仍由 LiquidBounce 管理。首次使用会把现有离线账号放入 Offline，其他账号放入 My；已有分组后，从主题外部新增的账号会留在 Root。更新前备份原生账号配置和主题持久化配置，不要把它们放进公开压缩包。

## 运行目标

面向带本项目 REST / Script API 的新版 LiquidBounce Nextgen。源码 API 基线为 **0.41.1**，本机现有环境为 **Minecraft 26.3 / LiquidBounce 0.41.0 / ScriptAPI 1.0.0+26.3 / Java 25**。其他游戏版本、原生后端与冷启动流程尚未全部实测；浏览器重载通过不代表游戏冷启动通过。

## 安装

1. 在 LiquidBounce 聊天栏执行 `.client theme browse`，打开主题目录。
2. 解压 `Opai-LiquidBounce-Theme.zip`，将里面的整个 `opai` 文件夹放入该目录。应形成 `themes/opai/metadata.json`，不要多套一层目录。
3. 执行 `.client theme reload`，再执行 `.client theme set opai`。更新时替换原来的 `opai` 文件夹，避免保留旧构建资源。
4. 返回主菜单查看效果。ClickGUI 仍使用 LiquidBounce 自己的打开按键，也可在主菜单按右 Shift 打开。主菜单左上角的三个快捷按钮已按要求删除。

首次更新后可关闭并重新打开 ClickGUI，使缓存的原网页实例重新加载。

恢复默认主题：`.client theme set liquidbounce`。

## 1.12.2 Windows 10 掉帧排查与跨平台修复

用户反馈1.9.0约500FPS、新版约60FPS。对照归档和官方资料后，确认了多余渲染监听、重复文本测量与网页同步游戏高帧率等开销路径；尚未在用户Windows原机确认唯一根因，不承诺恢复到500FPS。

- 网页Renderer独立最高60FPS，关闭网页SyncGameFps；不限制Minecraft帧率。只迁移一次，保留原来更低的上限及后续手动设置；原值写入opai.renderer.balanced60.v1.{HUD,ClickGUI}。不改GPU/VSync/画质。
- Bridge1.4.2仅在Dango3D模式注册世界渲染监听，普通HUD模式没有该每帧回调；按模式即时卸载。Nametags文本宽度按tick快照缓存，每帧共用字体解析；真实三段胶囊与像素爱心保留。
- Taco移动改用transform，避免每个动画帧改变left引发布局。原有HUD阴影外观保留。整组阴影改写实验在同帧节奏下未证明稳定收益，已撤回，不将阴影归为已确诊根因。
- Ctrl+Shift+F8诊断：Ctrl+Shift+F6轮换正常/关网页阴影滤镜/隐藏网页HUD；Ctrl+Shift+F7暂停或恢复本脚本绘制。关闭面板恢复，暂停脚本的租约2秒自动过期。键盘可在无鼠标的原生HUD操作。

这些代码路径在Windows/macOS共用，补丁同时生效；没有强开Accelerated Paint或替换JVM。完整试验、负面结果和官方来源见PERFORMANCE.md。

同时更新完整主题1.12.2与脚本1.4.2，仅留一份脚本后完全重启。Java音乐服务仍1.2.0，不更换客户端JAR。

验证：Svelte零错误/警告，27项脚本检查及最终12项专项检查通过。完整119项的末次运行中，一项并发动画空闲测试采样到额外调度；补充等待字体/通知结束的条件后，该项在最终专项复查通过。原始报告和重查均保留，不将功能检查等同于Windows实机性能结论。

## 1.12.1 Windows / macOS 音乐与动画减负

- 多个动画共用一个 RAF 与一个备用定时器；保留 Windows CEF 暂停 RAF 时的真实中间帧、回弹和重复打开动画。没有提高宿主 FPS 上限，也没有通过删除动画提速。

- Bridge 1.4.1 在普通 HUD 歌词模式跳过每帧 Java/Gson 的 3D 歌词调用，退出 Dango3D 只清理一次。
- 灵动岛延迟图标与数字间隔由 3.5px 改为 1px；延迟颜色仍连续变化，改用更鲜艳的绿 / 黄 / 橙 / 红。字号、图标尺寸和胶囊高度保持原值。

更新完整主题 1.12.1 与脚本 1.4.1，仅保留一个脚本副本，然后完全退出并重启游戏。Java 音乐服务仍为 1.2.0，无需更新客户端 JAR；收藏与账号数据目录不要删除。对比测试与局限见 PERFORMANCE.md。本版 115 项完整浏览器回归、23 项桥接脚本检查、Svelte 检查及资源打包校验通过；原生 Windows/macOS 游戏内帧率尚未实测。

- 灵动岛显示歌曲与当前歌词，模块通知和 Scaffold 计数优先，结束后恢复音乐卡。
- 支持 MP3、FLAC 和 PCM/WAV。部分 GD 来源返回 AAC/M4A 时会提示切换音乐源；默认网易云源。GD 不要求网易云账号，曲目是否可播放仍由来源决定；官方模式遵循账号本身的播放权限。

## Bridge 1.1.1 冷启动修复（主题仍为 1.8.1）

真实游戏日志显示 Script API 在 00:46:20 加载并启用 OpaiBounceScript.js，storage 配置在 00:46:30 才加载。ConfigSystem 加载配置会替换 PersistentLocalStorage.map。

旧脚本用 const Store = PersistentLocalStorage.INSTANCE.getMap() 永久保存了启动时的 Map。此后心跳写入旧 Map，预览请求也从旧 Map 读取；REST/主题访问的新 Map 则没有心跳。这解释了脚本报告 Loaded、主题却显示 Minecraft、ESP 预览同时失效的现象。

修复：每次 get/put/remove 都通过当前 singleton 的 getMap() 获取现用 Map。不会缓存 Map，也不会改写用户其他配置。

新增两个故障回归：启用后模拟配置替换 Map，验证心跳写到当前 Map；验证预览请求与功能控制从替换后的 Map 读取。旧版两个均失败，修复后共 16 项通过。

### 120 FPS 目标

动画跟随 `requestAnimationFrame` 与真实时间采样，不使用 30 FPS 定时器。原生 HUD 源码默认 `Renderer → Fps = 60`，菜单／ClickGUI 默认 `Fps = 0`（跟随显示器）。本版本首次发现 HUD 或 ClickGUI 的可用 Renderer 设置时，会把非零且偏低的上限提高到 **min(120, 接口允许的最大值)**，不会降低已有更高上限或修改 0（自动）。标记先持久化，再调用设置 API，避免 CEF 重建后重复迁移。之后手动调整会保留。

如客户端尚未提供 Renderer 节点或读取持久化失败，则跳过迁移。可在 HUD／ClickGUI 模块的 Renderer → Fps 手动检查。游戏 FPS 限制、VSync、显示器刷新率及 CEF 性能仍会影响实际帧率；本包没有经过游戏内 120 FPS 性能验收。

## 开发与构建

需要 Node.js 与 npm。打包脚本另需 Python 3。

```sh
cd opai-theme
npm ci
npm run check
npm run build
npm test
npm run package
```

浏览器测试使用本机 Google Chrome；在无 Chrome 的机器上可安装 Playwright Chromium 并修改 `playwright.config.ts` 的 `channel`。测试使用隔离的 API/WebSocket fixture，不会操作实际客户端账号或服务器。

在线开发：`npm run dev -- --host 127.0.0.1`，在客户端执行 `.client theme set http://127.0.0.1:5173/`。要从浏览器连接实际客户端，使用 `.client integration menu` 打开客户端生成的带端口链接。
